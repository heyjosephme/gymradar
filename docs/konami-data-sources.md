# Konami Sports Club — official data source investigation

Investigated 2026-11-03, 22:40–23:20 JST. Tools: `curl`, Playwright 1.64.1 driving Chrome (headless, `ja-JP`, `Asia/Tokyo`), manual review of the page's HTML, CSS and JavaScript.

## Summary

| Question | Finding |
| --- | --- |
| Where does 館内利用状況 come from? | **Server-rendered HTML** in the facility page. No JSON, XHR/fetch, embedded JS data or image endpoint is involved. |
| Representation | A text slot (`【HH:MM現在】` or `【営業時間外】`) plus a CSS class `congestion-thresshold{0-3}` (the misspelling is Konami's). Levels 1–3 are wordless pictograms with 1, 2 or 3 of 3 figures lit. Level 0 is hidden. |
| Scale | **3 levels**, not 5. Konami publishes no text labels and no thresholds. |
| Meaning | Calculated from check-ins (「チェックインの状況を基に算出しています。」). It is **not** a count of people physically present. |
| Timestamp | `HH:MM現在` in the page text, JST, no date and no seconds. All 14 samples found fall on :00 or :30. |
| Page polling/refresh | **None.** No polling, no meta refresh, and no DOM changes after load. To get a new value you have to request the page again. |
| Freshness class | **`official_periodic`**. The update cycle appears to be 30 minutes. That is inferred from the samples, not documented by Konami. |
| Cross-facility | Identical markup on all 7 Konami Sports Club pages checked. There is no widget on the junior-school page, and the Grancise brand uses a different template. |
| Usable for GymRadar? | Yes. Server-side fetch of `https://information.konamisportsclub.jp/ksc/{code}/` and HTML parsing. This is a public web page, **not a supported API**. |

Business-hours note: the main investigation ran after closing time on a national holiday (文化の日), which is also Meguro Aobadai's regular closing day (Tuesday), so it could only observe the outside-hours state. The business-hours format was first inferred from the markup, the CSS and search-engine-indexed copies of the pages. It was then **confirmed live on Saturday 2026-11-07 at 12:16 JST** on three clubs (§1.1). The widget's behaviour in the minutes around opening and closing is still unobserved.

## 1. Facility page

| Item | Value |
| --- | --- |
| URL | `https://information.konamisportsclub.jp/ksc/{facilityCode}/`, e.g. `/ksc/004446/` (Meguro Aobadai) |
| Method | `GET`, no query parameters |
| Response | `text/html;charset=UTF-8`, ~50–65 KB, generated by a Java backend (sets `JSESSIONID`) behind nginx |
| Auth | None |
| Cookies/session | Sets `JSESSIONID` (HttpOnly) and `visitorid`, but neither is required. Cookie-less requests return the full page. |
| Caching headers | None (`Cache-Control`, `ETag`, `Last-Modified` and `Age` are all absent). The page is generated per request. |
| CORS | No `Access-Control-Allow-Origin`, so browsers can't read it cross-origin. It must be fetched server-side. |
| robots.txt | `information.konamisportsclub.jp/robots.txt` disallows only `/trial_entry/` and `/*_R{1-8}.html$`. `/ksc/` is allowed. |
| Facility-specific | Yes. One page per facility code. Codes are listed by the directory endpoint (§4.2). |

### 1.1 館内利用状況 widget

```html
<!-- 混雑状況表示 -->
<div class="congestion">
  <ul>
    <li>館内利用状況</li>
    <li>【営業時間外】&nbsp;</li>
    <li class="congestion-img congestion-thresshold0"></li>
    <li>&nbsp;<a class="btn-category" href="#modal__root-congestion">？</a></li>
  </ul>
</div>
<!-- /混雑状況表示 -->
```

During business hours (observed live on 2026-11-07 at 12:16 JST, saved as `src/lib/fixtures/konami-004446-2026-11-07.html`):

```html
<li>【12:00現在】&nbsp;</li>
<li class="congestion-img congestion-thresshold2"></li>
```

That was 目黒青葉台 (level 2). 渋谷 and 恵比寿 showed `【12:00現在】` with `congestion-thresshold1` at the same moment. Level 3 hasn't been seen live, but `congestion-thresshold3` is the only other class the stylesheet defines.

Styling, from `/assets/css/common.css`:

```css
.congestion .congestion-thresshold0 { display:none }
.congestion .congestion-thresshold1 { background-image:url("/assets/img/icon-congestion-thresshold1.svg") }
.congestion .congestion-thresshold2 { background-image:url("/assets/img/icon-congestion-thresshold2.svg") }
.congestion .congestion-thresshold3 { background-image:url("/assets/img/icon-congestion-thresshold3.svg") }
```

The icons are 3 standing figures, no text. I rendered and inspected them:

| Class | Icon | GymRadar status |
| --- | --- | --- |
| `congestion-thresshold0` | hidden (`icon-…0.svg` returns 404) | `not_applicable`, shown together with `【営業時間外】` |
| `congestion-thresshold1` | 1 of 3 figures lit, blue `#15bde5` | `quiet` |
| `congestion-thresshold2` | 2 of 3 figures lit, amber `#e0b42e` | `moderate` |
| `congestion-thresshold3` | 3 of 3 figures lit, magenta `#e62f85` | `busy` |

The words `quiet`/`moderate`/`busy` are GymRadar's labels for an ordinal scale. Konami doesn't name the levels or publish thresholds, which may differ by facility. The UI always shows the official level next to the label ("level 2 of 3"). GymRadar never produces `very_quiet` or `very_busy` from this source, because the source doesn't have that resolution.

The explanation modal (`#modal__root-congestion`), verbatim:

> 館内利用状況について
> チェックインの状況を基に算出しています。
> 混雑時を避けてご利用いただくと快適にご利用できます。
> ご利用者が多い場合は、入場制限の可能性がありますので、ご協力のほどお願いします。
> ※更新タイミング等によっては実際の状況と異なる場合がございます。

Konami's video news 「コナミスポーツクラブの施設ホームページをリニューアル」 (2020-07; the URL now returns 410, so this is the search-indexed text) describes the same feature: the facility pages were renewed on 2020-07-06 with a 館内利用状況 display that shows "3段階" (3 levels) based on customer check-in information. The [2020-09-23 notice](https://www.konami.com/sportsclub/info/20200923/) lists 「施設の混雑状況のWEB公開」 as one of its infection-prevention measures.

### 1.2 How the value reaches the page (network evidence)

Playwright loaded `/ksc/004446/`, `/ksc/007871/` and `/ksc/006023/`, recorded every request and attached a `MutationObserver` to `.congestion` for 300 s per page:

- Each load made 61–63 requests: 1 document, 3 stylesheets, 8 scripts, 44–46 images and 5 XHRs. All 5 XHRs were Adobe Typekit font requests (`use.typekit.net`, `p.typekit.net`). None touched occupancy.
- The rendered widget DOM was byte-identical to the widget in the raw HTML response.
- There were **0 requests** after load, **0 mutations** and no `<meta http-equiv="refresh">`.
- Static review of all page scripts (`init.js`, `site.js`, `run.js`, `modal.js`, jQuery, slick) found no code that references `congestion`. The only `setTimeout` calls are UI timing (fonts, sliders, modals). The only AJAX calls are click-triggered modal loaders (§4.3).

Conclusion: the level and timestamp are computed when the server renders the page. They change only on a full reload, and there's no hidden endpoint to call instead.

### 1.3 Timestamp semantics and freshness

- `HH:MM現在` means "as of HH:MM" in JST (wall-clock time only). GymRadar treats it as `observedAt` on the current JST date, distinct from `retrievedAt` (when GymRadar fetched the page).
- Samples of the displayed time: your `22:30現在` plus search-indexed pages showing 18:00 (府中), 13:30 (武蔵境), 15:00 (五反田), 21:00 (船橋), 15:00 (渋谷), 16:00 (奏の杜), 16:00 (北千里), 16:00 (本店西宮アネックス), 12:00 (沖縄), 12:00 (グランサイズ), 16:30 and 11:30, and the live capture at 12:16:40 JST showing 12:00 (about 17 minutes old). That is 14 samples from 11+ facilities, and **all** fall on :00 or :30. With 10-minute granularity that would happen by chance less than once in a million; with 15-minute granularity, about once in 8,000. The value is most likely recomputed on a 30-minute cycle.
- The official wording 「更新タイミング等によっては実際の状況と異なる場合がございます」 also implies discrete update timings.
- **Classification: `official_periodic`**, check-in based, with a cycle of probably about 30 minutes. That cycle is inferred, not documented, and not guaranteed. A reading can lag reality by up to one cycle plus the time the server takes to publish it.
- GymRadar flags a reading as stale when `observedAt` is more than 60 minutes old (two cycles). Stale readings are shown with low confidence. Readings whose timestamp lies in the future relative to the server clock get no `observedAt` and are treated as stale.

### 1.4 What `【営業時間外】` does and doesn't tell us

At 22:40 on 2026-11-03, `【営業時間外】` + `thresshold0` appeared both on a **closed day** (目黒青葉台: Tuesday closing day) and **after closing on an open day** (渋谷, 恵比寿, 目黒, 碑文谷 and 五反田 were all open on holiday hours that ended between 18:00 and 21:00). The two cases are indistinguishable, so GymRadar never uses the widget to determine the closure reason. It is used only as a live cross-check against the official schedule:

- If the schedule says open now but the widget says `【営業時間外】`, the result is **unknown**: GymRadar reports conflicting signals and recommends checking before going.
- If the calendar says closed all day but the widget shows a reading, the result is likewise **unknown**.

Not yet observed: how the widget behaves in the first minutes after opening and at closing time. If it lags at opening, the first rule will show "unknown" briefly each morning. That errs on the side of caution, and it's listed under limitations.

## 2. Availability data on the same page

All of this is in the same HTML response, so no extra requests are needed.

### 2.1 Regular hours — `h3.hdg3-1` 「営業時間」 box

```html
<h3 class="hdg3-1">営業時間</h3>
<p>
[月水木金] 10:00～23:00<br>
[土日・祝休日] 10:00～21:00<br>
</p>
<p>[マシンジム・プール]<br/ >マシンジム及びプールのご利用時間/月・水・木・金=22:50/土日祝=20:50</p>
```

- The first `<p>` contains one line per day group: `[<days>(・祝休日)] HH:MM～HH:MM`. Day groups are concatenations of 日月火水木金土. A `・祝休日` suffix marks the range that applies on public holidays, and that range takes precedence over the weekday (碑文谷's page states this: 「土曜日が祝日の場合、祝日営業時間となります」). Formats observed: `[月水木金]`, `[火水木金]`, `[月火水木]`, `[土日・祝休日]`, `[土]`, `[日・祝休日]`. They are generated from the same structured data as the directory endpoint (§4.2).
- The following `<p>` elements are free-text `[title]` notes with no fixed format. Facility-specific closing rules live here:

| Facility | Official text | Gym/pool last use |
| --- | --- | --- |
| 目黒青葉台 004446 | マシンジム及びプールのご利用時間/月・水・木・金=22:50/土日祝=20:50 | 10 min before close |
| 渋谷 007871 | ご利用最終時間は、営業終了時間(最終チェックアウト時間)の15分前 | 15 min |
| 恵比寿 006023 | [運動エリア] ご利用最終時間は、営業終了時間…の30分前 | 30 min |
| 目黒 006022 | ジム&プール 営業終了15分前迄 | 15 min |
| 五反田 003930 | ご利用最終時間は営業終了30分前までです | 30 min |

  Because the wording varies, GymRadar doesn't parse these notes. Each favourite gym's rule is configured once in `src/config/gyms.ts`. The official text is shown verbatim on the dashboard so any drift is visible.
- `休館日` box: free text such as 「毎週火曜日、お盆、年末年始等」. It is shown for context and not parsed.

### 2.2 Business calendar — `#modal__root-calendar`

Covers the current and next month (`<p class="modal__box__title__text">2026年11月</p>`). Each day is `.calendar__body__cell`:

| Markup | Meaning (legend) |
| --- | --- |
| `<span class="calendar__body__cell is-close">` | 休館日: regular closing day |
| `<span class="calendar__body__cell is-close--extra">` | 臨時休館日: non-regular closure. Konami also uses it for year-end closures (12/30, 12/31). |
| `<a class="calendar__body__cell" onclick="return window.setModalNewsText(this, '…')">` | お知らせあり: a day with a notice. The notice text is inline. |
| `is-today`, `is-past` | presentation only |

Gotcha: on the junior-school page (007701), notice cells announcing a closure (「休館日となります。」, 「年末年始特別休館となります。」) **don't** carry `is-close`. So a notice day can't be assumed open. GymRadar treats a notice containing 「休館となります」 or 「休館日となります」 as closed and any other notice as **unknown**, showing the notice text.

### 2.3 Special business table — `#modal__root-day`

Titled per season (currently 「年末年始の営業情報」). Rows are `date | status icon | hours | note`:

```html
<tr><td>2026.12.30 (wed)</td><td class="align-center"><img src="/assets/img/icon-cross.png" alt="ばつ"></td><td></td><td>年末年始特別休館</td></tr>
```

The icon `alt` encodes the status: `まる` = 通常営業 (normal), `ばつ` = 休館 (closed), `ほし` = 特別営業 (special hours). The hours cell is `HH:MM～HH:MM` or empty. This table overrides the calendar and regular hours for the dates it lists. It can extend beyond the calendar's two months; for example, it lists 2027-01-01 to 01-05 while the calendar ends in December.

### 2.4 News notices (お知らせ)

News titles are in the page (`#tab__contents--01 .news__text`). Bodies load on click via a POST (§4.3), which GymRadar doesn't call. Some titles announce hours changes, e.g. 五反田's 「【重要】【クラブ会員様】施設利用時間のご案内/10月29日(木)～11月3日(火・祝)」. GymRadar can't interpret them. It surfaces titles that mention 営業時間, 利用時間, 休館 or 臨時休 on the gym's card as "official notices that may affect hours". They don't change the computed status.

### 2.5 Public holidays

Konami's `祝休日` ranges require knowing which dates are public holidays. GymRadar vendors the Cabinet Office list (`https://www8.cao.go.jp/chosei/shukujitsu/syukujitsu.csv`, Shift_JIS, retrieved 2026-11-03). That list covers through 2027-11-23 and includes 振替休日/国民の休日 (listed as 「休日」). Dates outside the vendored range (2026–2027) produce **unknown** hours rather than a guess.

### 2.6 How GymRadar determines a day's schedule

1. **Special table row for the date:** ばつ means closed. まる/ほし with hours means open with those hours.
2. **Calendar has no entry for the date:** unknown (outside the published two months).
3. **`is-close`:** closed, regular closing day. **`is-close--extra`:** closed, special or temporary closure.
4. **Notice cell:** closed if the notice announces a closure (「…休館となります」/「…休館日となります」), otherwise unknown with the notice text.
5. **Otherwise:** apply the single matching regular-hours range: the `祝休日` range on holidays, the weekday range on other days. If no range matches, more than one matches, or the hours couldn't be parsed, the result is unknown.

The result is "open", "closed" (with a reason) or "unknown" (with a reason). A gym is never reported open just because it isn't listed as closed: it must be inside the calendar's coverage and have explicit hours for the day type.

## 4. Endpoint inventory

### 4.1 Facility page

The primary source. See §1. Used by GymRadar.

### 4.2 Facility directory — `GET https://www.konami.com/sportsclub/api/facilities.php`

- Called by the official facility search (`/sportsclub/shisetsu/js/search_ui.js`, `$.ajax({ url: '/sportsclub/api/facilities.php', type: 'GET', dataType: 'json' })`).
- No parameters, no auth, no cookies required. Responds with `Cache-Control: no-cache, no-store`. CORS is limited to `https://img.konami.com`.
- JSON `{ facilities: [...] }` with 121 entries (2026-11-03), ~477 KB. Fields per entry: `code`, `name`, `nameKana`, `webPage`, `services`, `place.address`, `place.geographicCoordinates.{latitude,longitude}`, `telephones`, `businessHours.timeRanges[].{dayOfWeek.{sun..sat,holiday},beginTime,endTime}`, `businessHours.otherBusinessHours[].{title,comment}`, `receptionHours`, `closedDates[].comment`, `tags` (`ksc` / `grancise` / `xax-sportsspot`).
- Not facility-specific, and there's no per-day calendar, special hours or occupancy.
- Undocumented internal endpoint, so it isn't treated as a supported API. GymRadar doesn't call it at runtime. It was used once to look up coordinates for `src/config/gyms.ts`.

### 4.3 Modal content loaders (observed, not used)

From `/assets/js/modal.js`, triggered by clicks:

- `POST /ksc/modal/getNoticeDetail.jsp` with `mode=important|notice`, `entryId`, facility code and topic: the news body HTML.
- `POST /ksc/modal/getEquipDetail.jsp`: equipment detail HTML.

These are internal endpoints with side-channel semantics, they aren't needed, and GymRadar doesn't call them.

### 4.4 No occupancy endpoint

No JSON, XHR, fetch, WebSocket, EventSource or image request carries occupancy data. The only other XHRs are Typekit fonts.

## 5. Limitations

1. **Not an API.** GymRadar parses public HTML. Any redesign can break parsing. The parser is strict: anything unexpected becomes `unknown` and is never guessed.
2. **Check-in based.** The level reflects check-ins (and presumably check-outs), not people counted on the floor. Thresholds are unpublished and may differ by facility.
3. **Coarse and delayed.** There are 3 levels on an apparent ~30-minute cycle. A busy spike can take up to a cycle to show. Konami itself warns the display may differ from reality.
4. **Behaviour around opening and closing not yet observed.** The business-hours format was confirmed live on 2026-11-07, but not what the widget shows in the first minutes after opening or right at closing, and the 30-minute cycle is still inferred rather than watched across a boundary.
5. **Facility-specific closing times** are free text and configured manually per gym. Kids' school periods that block the pool or locker rooms (e.g. 五反田's [子供スクール時間] note) are only shown, not modelled.
6. **Hours changes announced only in news posts** are surfaced as titles, not interpreted.
7. **Calendar horizon** is two months. Holiday data is vendored for 2026–2027 and must be updated yearly (the Cabinet Office publishes the following year each February).
8. **Grancise and school-only facilities** aren't supported.

## 6. Recommended integration strategy (implemented)

- Fetch each favourite gym's facility page **server-side** (Astro on-demand rendering with the Node adapter). The page isn't readable cross-origin.
- **One request per gym per dashboard load, cached for 5 minutes** in memory. Sources update at most every ~30 minutes, so this keeps load on Konami negligible. Failures are cached for 1 minute. GymRadar sends an identifying `User-Agent` and respects robots.txt.
- Parse the widget, calendar, special table, regular hours, notes and schedule-related notice titles from that single response.
- Normalise occupancy as `official_periodic` with `observedAt` from `HH:MM現在`, `retrievedAt` from the fetch time, staleness at 60 minutes, and `not_applicable` whenever the gym is closed.
- Use the widget only as a cross-check for availability. The official schedule is the source of truth, and disagreements become `unknown`.
